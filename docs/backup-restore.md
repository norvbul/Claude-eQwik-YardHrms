# Backup & restore

Targets (RPO/RTO) are an owner decision to be set before go-live (NFR-004). The procedure below
supports, for example, RPO ≤ 15 minutes and RTO ≤ 4 hours.

## What must be backed up

| Asset | Contains | How |
|---|---|---|
| MySQL database | All tenant, payroll, licensing and audit data | Managed daily encrypted snapshots + point-in-time recovery (binlog), retained per policy; an extra snapshot before every release |
| Object storage bucket | Payslip PDFs, employee documents, payment evidence, logos, import files, bank files | Bucket versioning + replication or scheduled copy to a second region/account; object-lock if available |
| `FIELD_ENCRYPTION_KEY` | Decrypts TRN/NIS/NHT, bank accounts, MFA secrets | Secrets manager with its own backup; **without it encrypted fields are unrecoverable** |
| `TOKEN_HMAC_KEY` | Validates sessions, codes, email tokens | Secrets manager (losing it signs users out and voids unredeemed codes; no data loss) |
| Deployment config | Environment variables, image tags | Infrastructure-as-code repository / secrets manager |

Redis holds only rate-limit counters and needs no backup.

## Logical backup (self-managed MySQL or extra copy)

```bash
mysqldump --single-transaction --routines --triggers --events --set-gtid-purged=OFF \
  -h <host> -u <backup_user> -p yardhrms | gzip | \
  openssl enc -aes-256-cbc -pbkdf2 -salt -pass file:/run/secrets/backup_pass > yardhrms-$(date +%F).sql.gz.enc
```

`--triggers` matters: the append-only audit/ledger and payroll immutability rules are triggers.

## Restore procedure

1. Provision an empty MySQL 8.4 instance (or restore the managed snapshot / PITR to a **new** instance —
   never over the running one). Ensure `log_bin_trust_function_creators=1` if triggers will be created.
2. For a logical backup: decrypt, then `gunzip < … | mysql -h <host> -u <admin> -p yardhrms`.
3. Verify migrations are aligned: `pnpm exec prisma migrate status` (with `DATABASE_URL` pointing at the
   restored instance) must report the database schema up to date.
4. Restore the bucket (or point `S3_BUCKET` at the replica) for the same point in time as closely as
   possible. Payslip rows whose PDF is missing are regenerated by re-queuing `payslips.generate` for
   that run; employee documents and payment evidence cannot be regenerated.
5. Start the API with the **same** `FIELD_ENCRYPTION_KEY`; sign in and open an employee with a TRN and a
   payslip to confirm decryption and storage access.
6. Switch traffic (DNS / load balancer) and announce the recovery point to tenants if data was lost.

## Quarterly restore test

1. Restore the latest snapshot and bucket copy into an isolated environment (no outbound email: leave
   `SMTP_HOST` pointing at a sink such as Mailpit).
2. Run `pnpm exec prisma migrate status`, start the stack, and check: sign-in with MFA, a locked payroll
   run and its payslip, leave balances, a subscription's state, the audit log.
3. Record duration (RTO achieved), recovery point (RPO achieved), issues and sign-off. Destroy the
   environment afterwards — it contains production personal data.
